# Модели распознавания эмоций по голосу и лицу — правила использования

Документ для ассистента (Claude) и разработчика на целевом устройстве. Здесь всё, что нужно,
чтобы встроить модели в систему видеонаблюдения: что лежит в архиве, точная предобработка,
контракты входов и выходов, выбор алгоритмов, слияние модальностей и ограничения.

**Коротко.** Две независимые модели — аудио (голос) и видео (лицо) — выдают по каждому окну
распределение по 6 эмоциям. Затем выходы сшиваются одним из 6 алгоритмов слияния.
Всё работает на CPU через ONNX Runtime (fp32 или int8). Исходные веса PyTorch приложены.

## 2. Установка и самопроверка

```bash
pip install -r requirements.txt
python -m emotion_kit.selftest           # ONNX fp32 и int8 против эталона
python -m emotion_kit.selftest --torch   # дополнительно PyTorch (нужны torch, torchvision, transformers)
```

Первый вызов после запуска медленнее на несколько секунд: librosa компилирует функции (numba), ONNX Runtime
готовит графы. Мерьте скорость со второго окна.

Самопроверка обязательна после копирования: fp32 должен совпасть с эталоном до ~1e-3, у int8 должен
совпасть класс. Если что-то не так, файлы повреждены — сверьте SHA-256 с `models/manifest.json`.

Разбор одного клипа:

```bash
python -m emotion_kit.cli --video clip.mp4 --fusion all              # звук берётся из видео через ffmpeg
python -m emotion_kit.cli --video clip.mp4 --audio clip.wav --precision int8 --frames 8
```

## 3. Модели отдельных модальностей

Обе модели обучены на CREMA-D: 91 актёр, 6 эмоций, задуманная актёром эмоция как метка.
Оценка диктор-независимая: тестовые актёры не участвовали ни в обучении, ни в выборе.

### 3.1. Аудио: WavLM-Base+ с взвешенной суммой слоёв

- Архитектура: WavLM-Base+ (94.7 млн параметров), дообучен целиком, кроме свёрточного входа.
  Дальше обучаемая взвешенная сумма 13 скрытых слоёв, проекция 768→256, пулинг с вниманием по
  времени, линейный слой на 6 классов.
- Вход: `wave` — float32 `(1, L)`, 16 кГц, L — любое (динамическая ось `samples`).
  Обучалось на 0.3–4 с.
- Выход: `logits (1, 6)`, `emb (1, 256)`. `emb` — вход алгоритма `stack_hidden`.

**Предобработка аудио** (`emotion_kit.preprocess.prepare_audio`, менять нельзя):
1. моно, ресемплинг в 16 кГц;
2. обрезка тишины по краям: `librosa.effects.trim(top_db=30)`;
3. нормировка по пику: `y / max|y|`;
4. если длиннее 4 с — центральный фрагмент 4 с;
5. если после обрезки короче 0.3 с или пик < 1e-4 — речи нет, аудио считается отсутствующим.

Нормировка по пику означает, что громкость не несёт информации. Тихая речь усиливается вместе с
шумом, поэтому на тихих участках с фоновым шумом модель ненадёжна (см. п. 6).

### 3.2. Видео: FER-Swin-T по кадрам + временной трансформер

- Архитектура: Swin-T (предобучен на распознавании выражений лица, дообучен) превращает каждый
  кадр в вектор 768. Дальше проекция 256, синусоидальная кодировка времени кадра, 1 слой
  трансформера (4 головы), пулинг с вниманием, 6 классов.
- Два ONNX-графа:
  - `video_frame_encoder_swin_t*.onnx`: `frames (N, 3, 224, 224)` → `feat (N, 768)`; кадры
    независимы, N любое;
  - `video_temporal_head.onnx`: `feats (1, T, 768)`, `times (1, T)` → `logits (1, 6)`, `emb (1, 256)`.
- Разделение сделано для потока. Кадры можно кодировать по мере поступления, кэшировать их
  признаки, а голову (доли миллисекунды) запускать по скользящему окну.

**Предобработка видео** (`preprocess.FaceCropper`, `faces_to_input`, `frame_times`):
1. окно клипа → 16 кадров равномерно (`np.linspace(0, n-1, 16).round()`);
2. детекция лиц YuNet (порог 0.6) на каждом из 16 кадров, в кадре берётся самое крупное лицо;
3. **одна рамка на окно** — медиана рамок по кадрам (дрожание покадровой рамки ухудшает качество);
4. рамка расширяется на 25 % ширины/высоты с каждой стороны и обрезается по границам кадра;
5. кроп → `cv2.resize(224, 224, INTER_AREA)` без сохранения пропорций, RGB;
6. `x / 255`, нормировка ImageNet: mean `(0.485, 0.456, 0.406)`, std `(0.229, 0.224, 0.225)`, CHW;
7. времена кадров в секундах на шкале 0..3: `t_k = (k + 0.5) / 16 * 3`, k — номер кадра из 16.
   Шкала фиксирована и не зависит от реальной длительности окна: так обучалась модель.

Режим **8 кадров**: кодируются только кадры k = 1, 3, …, 15 из тех же 16, с теми же `t_k`
(`frame_times(8)` возвращает и времена, и индексы). Это вдвое дешевле.

Если лицо не найдено ни на одном кадре окна, видео считается отсутствующим. Не подавайте
центральный кроп: на кадре без лица модель выдаёт уверенный мусор.

| аудио | исходная PyTorch (GPU) | 0.751 | — | — |
| аудио | ONNX fp32 | 0.751 | 100.0 % | 87 мс |
| аудио | ONNX int8 | 0.745 | 97.6 % | 65 мс |
| видео | исходная PyTorch (GPU), 16 кадров | 0.714 | — | — |
| видео | ONNX fp32, 16 кадров | 0.714 | 100.0 % | 783 мс |

Слияние поверх ONNX-выходов на том же тесте (UAR, чистые входы):

| Метод | fp32, 16 кадров | fp32, 8 кадров | int8, 16 кадров | int8, 8 кадров |
|---|---|---|---|---|
| `weighted_logits` | 0.856 | 0.854 | 0.855 | 0.857 |
| `weighted_logits_robust` | 0.853 | 0.849 | 0.854 | 0.850 |
| `mean_probs` | 0.836 | 0.837 | 0.834 | 0.838 |
| `confidence_weighted` | 0.854 | 0.852 | 0.851 | 0.854 |
| `stack_logits` | 0.859 | 0.856 | 0.858 | 0.856 |
| `stack_hidden` | 0.861 | 0.865 | 0.866 | 0.864 |

**Как выбирать:**

- **ONNX fp32, 16 кадров** — эталон, выходы совпадают с исходной моделью до ~1e-5.
- **ONNX int8 — рекомендуемый вариант для CPU.** Файлы меньше (аудио 123 МБ вместо 379, видео 31 вместо 113), быстрее, потеря на отдельных модальностях ~0.5 п.п., а качество слияния то же, что у fp32 (параметры слияния обучены на fp32-выходах и подходят без изменений). Квантизованы только матричные умножения (dynamic int8, поканально).
- **8 кадров** — видео вдвое дешевле; потеря качества — по таблице.
- **PyTorch (.pt)** — исходный формат для дообучения, анализа или GPU. На CPU не быстрее ONNX.
  Нужны `torch`, `torchvision`, `transformers`; определения моделей — `emotion_kit/torch_models.py`.

## 4. Слияние модальностей

Все алгоритмы работают поверх выходов двух моделей одного окна (`emotion_kit.fusion.Fusion`).
Обучение на устройстве не нужно: параметры — в `models/fusion_params.json`.

| Метод (`fusion=`) | Что делает | Параметры |
|---|---|---|
| `weighted_logits` | `α·logits_a + (1−α)·logits_v` | α, подобран на чистых данных |
| `weighted_logits_robust` | то же | α, подобран на смеси порченых данных |
| `mean_probs` | среднее вероятностей двух моделей | нет |
| `confidence_weighted` | вес модальности на окне = её уверенность `log 6 − H(p)`, сумма log-вероятностей | нет |
| `stack_logits` | логистическая регрессия на `[logits_a, logits_v]` (12 признаков) | standardize + W (6×12) + b |
| `stack_hidden` | логистическая регрессия на `[emb_a, emb_v]` (512 признаков) | standardize + W (6×512) + b |
| `audio_only` / `video_only` | одна модальность | нет |

Формула стекинга: `scores = ((x − mean) / scale) @ coefᵀ + intercept`, `probs = softmax(scores)`.
У `stack_*` вероятности откалиброваны логрегрессией. У остальных методов `softmax` от слитых
логитов — это не калиброванная вероятность, используйте для ранжирования и порогов
осторожно.

**Отсутствующая модальность.** Если одной модальности в окне нет (`prepare_audio` вернул None
или лицо не найдено), любой метод автоматически переходит на оставшуюся
(`used: "<метод> -> video_only (нет аудио)"`). Это правильнее, чем подавать нули: при «пустом»
входе все методы слияния хуже одной сохранной модальности (см. строки `a_missing` и
`v_missing` ниже).

### 4.2. Какой метод выбрать

- **По умолчанию для видеонаблюдения — `stack_hidden`.** Он лучший или почти лучший во всех
  условиях. На чистых данных он не хуже простых методов, а при шуме в звуке заметно лучше
  (многоголосый шум 0 дБ: 0.690 против 0.458 у `weighted_logits`). Цена — нужен `emb` обеих
  моделей (он и так есть в выходе) и 512×6 умножений.
- **Тихое помещение, хороший звук, нужна простота и прозрачность — `weighted_logits`.**
  Один параметр α, понятен человеку.
- **Звук обычно чистый, а лицо часто плохо видно — `confidence_weighted`.** Лучший при порче
  видео (0.780), обучения не требует. Но при шуме в аудио он худший: аудиомодель на шуме
  остаётся уверенной и ошибается.
- **Нужна устойчивость, но только по логитам (например, модели заменят) — `stack_logits`.**
- `mean_probs` — только как простая база для сравнения.
- `audio_only` / `video_only` — когда другая модальность заведомо отсутствует или отключена.
- Пользователю системы можно дать переключатель. Метод задаётся параметром
  `EmotionPipeline(fusion=...)` или `analyze(..., methods=[...])` — можно получать несколько сразу.

## 5. Встраивание в систему видеонаблюдения

```python
from emotion_kit import EmotionPipeline

pipe = EmotionPipeline(backend="onnx", precision="int8", n_frames=16, fusion="stack_hidden", threads=4)

# на каждое окно (рекомендуется 2–4 с, шаг 1–2 с) и каждого отслеживаемого человека:
res = pipe.analyze(audio=wave_window, sr=16000,          # np.float32 (L,) или None
                   frames=rgb_frames_window,             # список кадров RGB uint8 (H, W, 3) или None
                   face_box=(x, y, w, h),                # рамка человека от трекера; None — самое крупное лицо
                   methods=["stack_hidden", "weighted_logits"])
# res = {"audio": {"label", "probs"} | None, "video": {...} | None,
#        "fusion": {"stack_hidden": {"label", "used", "probs"}, ...}}
```

Низкоуровневые вызовы, если нужен свой конвейер:
- `pipe.run_audio(wave, sr)` → `{"logits", "probs", "emb"}` или None;
- `pipe.run_video(frames, face_box)` → то же или None;
- `pipe.fusion.fuse(method, a, v)` → `{"method", "scores", "probs", "label"}`;
- `VideoONNX.encode_frames` + `predict_features` — для кэширования признаков кадров в потоке.
- `preprocess.read_audio_ffmpeg(path)` — звуковая дорожка любого медиафайла (mp4, flv, mkv) в моно 16 кГц;
  `preprocess.read_video_frames(path)` — 16 кадров файла равномерно.

Правила окна:
1. **Длительность.** Модели обучены на клипах 1–4 с с одной эмоцией (средняя длина речи после обрезки тишины 2.4 с).
   Окно 2–4 с с перекрытием; длиннее 4 с аудио всё равно обрезается до центральных 4 с.
2. **Синхронность.** Звук и кадры окна должны относиться к одному интервалу времени
   и к одному человеку.
3. **Кто говорит.** Аудиомодель не знает, чей голос. При нескольких людях в кадре свяжите речь
   с говорящим (диаризация или детекция активного говорящего) либо используйте
   `video_only` для молчащих.
4. **Несколько лиц.** `FaceCropper.detect(frame)` возвращает все лица. Ведите трек каждого
   человека и передавайте его рамку в `face_box`, иначе берётся самое крупное лицо в окне.
5. **Сглаживание.** Эмоция меняется медленнее окна. Усредняйте `probs` по 2–3 соседним окнам
   (или экспоненциально) и не реагируйте на одиночный всплеск.
6. **Порог отказа.** Если максимум `probs` < 0.4, выдавайте «не определено» вместо класса.
   Для `stack_*` это осмысленная вероятность, для остальных — ориентир.

## 6. Ограничения — обязательно учитывать

- **Домен.** CREMA-D — актёрская постановочная речь на английском, 12 нейтральных по смыслу фраз,
  студийный звук, фронтальное лицо крупным планом, ровный свет. На камерах наблюдения (ракурс
  сверху, мелкое лицо, сжатие, реверберация, другой язык) качество будет ниже табличного.
  Насколько ниже, неизвестно без своей разметки. Перед выводами о людях проверьте на своих данных.
- **Задуманная, а не испытываемая эмоция.** Модели учились угадывать эмоцию, которую актёр
  играл по заданию. Это не детектор внутреннего состояния человека. Люди-оценщики CREMA-D
  совпадали с задуманной эмоцией в 41 % (голос), 58 % (лицо) и 64 % (аудиовизуально) случаев.
  Ошибки моделей сосредоточены на тех же неоднозначных клипах.
- **Смещения.** Видеомодель на 9 п.п. хуже на людях 50+ лет, чем на 20–29-летних. У людей-оценщиков
  такой разницы нет, то есть это перекос модели. Слияние уменьшает его до ~5 п.п. Женщин
  распознают лучше на 4–8 п.п., но это свойство корпуса, у людей-оценщиков то же самое.
- **Слабые классы.** Грусть по лицу распознаётся плохо (полнота 0.36), страх по обоим каналам
  ~0.62. Слитая модель: грусть 0.67, страх 0.72; гнев, радость и нейтральное ≥ 0.92.
- **Громкость не используется** (нормировка по пику). Крик и тихая речь различаются только тембром
  и интонацией.
- **Ответственность.** Не используйте выходы как единственное основание для решений о людях
  (допуск, санкции, оценка сотрудников). Результат — вероятностная подсказка оператору.

## 7. Происхождение и воспроизводимость

- Экспортирован фолд **s1_f3** из 10 прогонов исследования (5 фолдов по актёрам × 2 сида). Обе модели и параметры слияния — с одного фолда, это обязательно: слияние обучено на выходах именно этих моделей.
- Почему этот фолд: второй по сумме val UAR аудио и видео, и при этом высокий на тесте. Ожидаемое качество на новых людях того же домена — средние по 10 прогонам (п. 4.1: аудио 0.761, видео 0.689, слияние 0.840), а не числа этого фолда.
- Актёры CREMA-D: обучение — 58, выбор эпохи и обучение слияния (val) — 15, тест — 18: 1011, 1014, 1020, 1022, 1023, 1025, 1027, 1029, 1032, 1043, 1045, 1046, 1050, 1051, 1061, 1065, 1073, 1089. Не проверяйте модели на клипах обучающих актёров: результат будет завышен.
- Обучение аудио: 6 эпох, AdamW, lr 2e-5 энкодер / 1e-3 голова, OneCycle, веса классов, аугментация громкостью ±6 дБ и шумом SNR 15–40 дБ.
- Обучение видео: 8 эпох (не меньше 5), lr 3e-5 / 1e-3, label smoothing 0.1, 8 случайных кадров (по одному из 8 сегментов) при обучении и 16 при оценке, общая для клипа аугментация кроп/поворот/отражение/цвет/стирание. Кропы лица при обучении хранились в JPEG (качество 92), при работе подаются несжатые; влияние этой разницы не измерялось.
- Слияние: `weighted_logits` — α по сетке 0..1 на val; `*_robust`, `stack_*` — на val, где каждый клип взят трижды: чистым, со случайной порчей аудио и со случайной порчей видео; логрегрессия — StandardScaler + LogisticRegression(class_weight='balanced'), C подобран внутренней GroupKFold по актёрам.

- Полный пайплайн исследования, отчёты и скрипты экспорта — в исходном проекте
  (`scripts/export_models.py`, `scripts/export_eval.py`).
- Метрика UAR — средняя по классам полнота (macro-recall); WA — доля верных.
