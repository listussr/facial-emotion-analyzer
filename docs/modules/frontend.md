# `frontend` — веб-интерфейс

React 18 + TypeScript + Vite + Tailwind CSS. В Docker собирается в статику и раздаётся nginx, который
проксирует `/api` и WebSocket на webapp. При разработке — `npm run dev` на порту 5173 с прокси на :8000.

```
frontend/
├── nginx.conf               прокси /api и WebSocket на webapp, /api/capture — на ingest, поток записей
├── vite.config.ts           прокси для dev-сервера
└── src/
    ├── router.tsx           маршруты; старые /cameras/:id и /uploads/:id ведут на /session/:id
    ├── api/client.ts        REST-клиент и DTO
    ├── types/index.ts       типы сессий, эмоций, истории, записей
    ├── pages/               HomePage, SessionPage, RecordingsPage, HistoryPage, UserHistoryPage, SettingsPage, AboutPage
    ├── components/          Header, Layout, StreamTile, EmotionBars, RecordingChip, BrowserCaptureBar, Toggle,
    │   ├── live/            LiveVideo, sync.ts: показ кадров с рамками
    │   └── charts/          графики истории
    ├── capture/             browserCapture.ts, useBrowserCapture.ts: камера браузера
    ├── hooks/               useSessions, useSessionEvents, useLiveFaceStats, useAnalysisDefaults, useUiPrefs
    └── data/                models.ts (модели и методы слияния с подписями), sessionStatus.ts
```

---

## Разделы

| Маршрут | Страница | Что на ней |
|---|---|---|
| `/` | `HomePage` | новый анализ в три шага (источник, что анализировать, название); идущие и завершённые сессии |
| `/session/:id` | `SessionPage` | видео с рамками, кто в кадре и его эмоция, голос, «Остановить»; свёрнуты статистика по людям и технические подробности |
| `/recordings[/:id]` | `RecordingsPage` | итоговые записи: плеер, распределения эмоций, скачивание mp4 и JSON, удаление; `?t=секунды` открывает видео на этой секунде (ссылки из отчётов агента) |
| `/history`, `/history/:userId` | `HistoryPage`, `UserHistoryPage` | поиск человека по фото, история его эмоций, CSV |
| `/settings` | `SettingsPage` | параметры по умолчанию для новых анализов; блок «Хранение» — объём записей и загрузок и сроки их автоочистки (`/api/storage`) |
| `/about` | `AboutPage` | что делает система, модели, стадии обработки, точность и скорость, ограничения и этика |

Шапка показывает связь с сервером и готовность анализа по `/api/health`. Пока сервисы загружают модели,
горит «модели загружаются…», а причины видны во всплывающей подсказке. В это время опрос идёт раз в 3 с,
в остальное время — раз в 10 с.

## Параметры анализа

`useAnalysisDefaults` хранит параметры по умолчанию в `localStorage` и синхронизирует их между вкладками.
На странице «Настройки» они собраны понятными словами:

- **Режим** «Быстро» / «Точнее» — сразу модель лица, модель голоса и кадры на окно (int8 + 8 кадров или
  fp32 + 16 кадров);
- частота анализа (10 / 15 / 20 / 30 кадров в секунду), узнавание людей, способ объединения лица и голоса;
- модели по отдельности, трекер и CPU/GPU — в свёрнутом блоке «Для специалистов»;
- «Вернуть рекомендуемые».

`toSessionConfig(defaults, modalities)` превращает их в конфиг сессии для API. На главной пользователь
выбирает только источник и что анализировать.

## Живое видео (`components/live/`)

Кадры (`/api/live`) приходят сразу, аналитика (`/api/events`) — с задержкой на детекцию, модели и слияние.
`LiveVideo`:

1. декодирует JPEG в `ImageBitmap` и держит буфер кадров по `pts` (4 с);
2. оценивает отставание аналитики (`LagEstimator`, EMA) и показывает кадр с задержкой на эту величину плюс
   80 мс (не больше 2 с);
3. для показанного кадра интерполирует рамки между двумя ближайшими результатами аналитики по времени; если
   результат старше кадра больше чем на 600 мс, рамки не рисуются;
4. если аналитики нет дольше 2 с, показывает видео без задержки и без рамок.

Так рамки совпадают с лицом даже при детекции раз в два кадра и при анализе медленнее источника.

## Камера браузера (`capture/browserCapture.ts`)

Модуль-синглтон вне React-дерева, поэтому захват не прерывается при переходах между страницами. Состояние
показывает плашка `BrowserCaptureBar` в углу экрана (превью, счётчики, «Остановить»).

1. `getUserMedia` — камера до 1280×720 и микрофон (эхоподавление включено, шумоподавление и автоусиление
   выключены, чтобы не искажать голос). Браузер даёт камеру только на `localhost` или по HTTPS. Если
   страница открыта по HTTP с другого устройства, пользователь видит адрес `https://<хост>:8443`.
2. `POST /api/sessions/browser` с модальностями, которые реально дал браузер.
3. WebSocket `/api/capture/{id}` — nginx ведёт его прямо в сервис приёма (`ingest`):
   - **кадры** — по таймеру с частотой сессии: canvas уменьшает кадр до 640×480 и кодирует в JPEG
     (качество 0.75). Если в сокете больше 512 КБ неотправленного, кадр пропускается;
   - **звук** — AudioWorklet усредняет сэмплы до 16 кГц моно и отдаёт пакеты по 100 мс; `pts` считается по
     счётчику сэмплов от первого пакета.
4. Закрытие сокета (кнопка, закрытие вкладки) останавливает сессию на сервере.

Доступ к камере браузеры дают только на `localhost` или по HTTPS.

## Данные сессии

- `useSessions(kind?)` — опрос списка сессий раз в 2–3 с, остановка сессии.
- `useSessionEvents(id)` — WebSocket аналитики: последний результат, связь, частота.
- `useLiveFaceStats(latest)` — распределение эмоций по лицам, которые сейчас в кадре (обновляется раз в секунду).
- `RecordingChip` — статус итоговой записи на странице сессии; опрашивает API, пока запись не готова.

## Стиль

Белые карточки (`.glass`), одна основная кнопка на экран, сегментные переключатели (`.seg`) и карточки выбора
(`.choice`). Определения — в `src/index.css`. Вёрстка проверена на ширине телефона: меню и карточки выбора
перестраиваются, горизонтальной прокрутки нет.
