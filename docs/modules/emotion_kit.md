# `emotion_kit` — модели CREMA-D

Инференс моделей эмоций, обученных в отдельном исследовательском проекте на CREMA-D, и методы слияния
модальностей. Пакет перенесён без изменений вместе с моделями (`crema_emotion_models.zip`); подробные
правила использования — `models/crema/usage_rules.md`.

```
src/emotion_kit/
├── backends.py     AudioONNX, VideoONNX (fp32 / int8), AudioTorch, VideoTorch, load_backends, manifest
├── preprocess.py   prepare_audio, FaceCropper (YuNet), faces_to_input, frame_times, чтение файлов
├── fusion.py       Fusion: 8 методов слияния на numpy
├── pipeline.py     EmotionPipeline: окно (звук + кадры) → эмоции по звуку, видео и после слияния
├── torch_models.py определения моделей PyTorch (для backend="torch")
├── selftest.py     проверка установки по эталонным выходам selftest.npz
└── cli.py          разбор одного клипа из командной строки
```

Код системы использует `backends`, `preprocess` и `fusion`; `pipeline` и `cli` — для офлайн-проверки клипов.

---

## Модели (`models/crema/`)

| Файл | Что это | Вход → выход |
|---|---|---|
| `video_frame_encoder_swin_t[_int8].onnx` | Swin-T, кадровый энкодер | кадр 224×224 → 768 |
| `video_temporal_head.onnx` | временной трансформер | T×768 + времена кадров → логиты (6) и эмбеддинг (256) |
| `audio_wavlm_base_plus[_int8].onnx` | WavLM-Base+ | волна 16 кГц (до 4 с) → логиты (6) и эмбеддинг |
| `face_detection_yunet_2023mar.onnx` | детектор YuNet | — |
| `fusion_params.json` | параметры обученных методов слияния | — |
| `manifest.json`, `eval.json`, `selftest.npz` | описание, отчёт о качестве, эталоны | — |

Каталог задаётся `CREMA_MODELS_DIR` (по умолчанию `models/crema` от корня репозитория). Веса в git не
хранятся; в Docker каталог монтируется только для чтения.

## Качество

UAR (средняя по классам полнота), диктор-независимо, среднее по 10 прогонам (5 фолдов × 2 сида):

| Модальность | UAR |
|---|---:|
| лицо | 0.689 |
| голос | 0.761 |
| слияние `stack_hidden` | 0.840 |

`stack_hidden` лучше всех и под шумом: при белом шуме 0 дБ голос сам по себе падает до 0.44 UAR, а слияние
держит около 0.81 (по фолду модели, `eval.json`).

## Предобработка — как при обучении

- **Звук** — `prepare_audio(y, sr)`: моно 16 кГц, обрезка тишины, нормировка по пику, не длиннее 4 с; если
  речи меньше 0.3 с — `None`.
- **Лицо** — кроп YuNet с запасом 25 %, resize в 224×224 без сохранения пропорций, нормировка ImageNet
  (`faces_to_input`).
- **Время кадров** — `frame_times(n)`: шкала 0..3 с, 16 кадров при обучении; для 8 кадров — центры сегментов.

Видеопайплайн повторяет эту предобработку в `clip_window.py`, потому что кадры приходят потоком, а не
файлом.

## Слияние (`Fusion.fuse(method, a, v)`)

`a` и `v` — выходы аудио- и видеомодели (`logits`, `emb`) или `None`, если модальности нет. Методы:
`stack_hidden`, `stack_logits`, `weighted_logits`, `weighted_logits_robust`, `confidence_weighted`,
`mean_probs`, `audio_only`, `video_only`. Результат — вероятности и фактически применённый метод (при
отсутствии модальности метод переходит на оставшуюся).

## Проверка установки

```bash
python -m src.emotion_kit.selftest
```

Сверяет выходы всех бэкендов с эталонами `selftest.npz`. Нужен после обновления моделей или ONNX Runtime.

## Почему без правок

Пакет — общий код с проектом обучения. Его стиль не приводился к стилю репозитория и не менялся, чтобы новые
версии моделей и кода можно было переносить заменой файлов. Единственное отличие — пути к моделям берутся
из `CREMA_MODELS_DIR`, а сессии ONNX Runtime не крутят потоки в ожидании (`allow_spinning = 0`).
