# `agent` — разбор сессии и отчёт

Пакет агента-аналитика ([AGENT.md](../AGENT.md)): подготовка разбора, цикл с моделью и ручками MCP, проверка
ответов, отчёт и файлы разбора.
- **Без модели** отчёт собирается по данным детекторов. Это запасной режим, когда LLM недоступна, и базовая
  линия для оценки.
- **Цикл с моделью** проверен тестами с поддельной моделью. Прогон с настоящей моделью (Qwen через Ollama)
  ещё не делался.
- **Сервис** с очередью и страницей «Разборы» — этап 5.

```
src/agent/
├── config.py        AgentConfig: agent.yaml + переменные AGENT_*
├── llm.py           LLMClient: OpenAI-совместимый /chat/completions с инструментами, повторы, LLMError
├── mcp_bridge.py    MCPBridge: mcp_server.py дочерним процессом, ручки → инструменты, метки c1, c2, …
├── prompts.py       системный промпт, промпты момента и итога, схемы submit_finding и submit_summary
├── validate.py      проверка вердикта и итога кодом
├── loop.py          AgentLoop: фазы 2–4 (моменты, итог, проверка), бюджеты, запасной режим
├── trace.py         журнал trace.jsonl
├── run.py           prepare_run: ряд → обзор и моменты (фаза 1)
├── runner.py        analyze: разбор сессии целиком
├── store.py         run.json, findings.json, report.html, trace.jsonl; загрузка в бакет агента
├── findings.py      Finding, Evidence, RunData; порядок карточек, findings.json
├── report.py        build_report → HTML
├── charts.py        SVG (matplotlib): таймлайн, мини-графики
├── templates/report.html.j2
└── __main__.py      python -m src.agent
agent.yaml           настройки агента
```

## Запуск

Только детекторы:

```bash
python -m src.agent path/to/series.json
```

С моделью из `agent.yaml`:

```bash
python -m src.agent --session upload_ab12cd --llm
```

Модель на другом ПК, результат — в бакет агента:

```bash
python -m src.agent --session upload_ab12cd --llm --base-url http://192.168.1.20:11434/v1 --upload
```

- **Файлы.** В `data/agent_runs/<run_id>/` появляются `report.html`, `findings.json`, `run.json`, а с моделью —
  ещё `trace.jsonl`. С `--upload` они копируются в бакет `affectra-agent-reports` (`runs/<run_id>/…`) ключом
  `agent` (`S3_AGENT_*`).
- **Права.** С `--session` данные сессии читаются ключом и ролью только на чтение (`S3_READER_*`,
  `DB_READER_PASSWORD`). MCP-сервер получает те же права.

## Настройки (`agent.yaml`)

| Раздел | Параметр | По умолчанию | Смысл |
|---|---|---|---|
| `llm` | `base_url` | `http://localhost:11434/v1` | OpenAI-совместимый сервер: Ollama, llama.cpp, vLLM, внешний API; `AGENT_LLM_BASE_URL` |
| | `model` | `qwen3:4b` | модель; точное имя выбирается при загрузке; `AGENT_LLM_MODEL` |
| | `temperature`, `seed` | 0.2, 7 | для воспроизводимости |
| | `max_tokens`, `timeout_s` | 900, 180 | ответ модели |
| | `no_think` | `true` | пометка `/no_think` для Qwen: без режима «размышлений» |
| | `extra_body` | `{}` | дополнительные поля запроса для конкретного сервера |

| | `top_k` | 10 | моментов с разбором моделью |

| | `time_budget_s` | 900 | на весь разбор |
| | `output_dir` | `data/agent_runs` | каталог разборов |

## Цикл (`AgentLoop`)

1. **Обзор сессии.** Агент сам вызывает `get_session_overview`, это первый результат с меткой `c1`.
2. **Разбор моментов.** Каждый из `top_k` самых значимых моментов разбирается в отдельном диалоге:
   системный промпт (с добавкой `prompt_notes` профиля) и сообщение с обзором и данными детекторов (метка
   `c0`). Модели доступны ручки MCP и `submit_finding`.
   - Результат каждого вызова приходит с меткой `[cN]`, и доказательства должны ссылаться на эти метки.
   - Повтор вызова с теми же аргументами в пределах момента не исполняется: модель получает ссылку на прежний
     результат.
   - После `max_tool_calls` вызовов ручки не исполняются: модель получает требование вызвать
     `submit_finding`.
   - **Запасной режим.** Если модель написала JSON текстом вместо вызова, он разбирается так же. Если просто
     текст, модель получает напоминание.
3. **Проверка** (`validate_finding`):
   - вердикт, уверенность и значимость — из допустимых значений;
   - суть и объяснение не пустые;
   - у «стоит посмотреть» и «вероятно, артефакт» есть доказательства, и каждое ссылается на метку, реально
     доступную в этом диалоге;
   - времена мм:сс в текстах — не дальше 30 с от момента.
   
   При ошибке модель один раз получает её текст. Если и после этого не прошло, момент остаётся «без оценки
   модели».
4. **Итог.** Модель без ручек получает вердикты и вызывает `submit_summary` (заголовок объявления и итог). Если
   не вышло, используется шаблонный заголовок.
5. **Статус.** Если модель недоступна, исчерпано время или у какого-то момента нет вердикта, статус —
   `partial`, причина записывается в `notes`. Отчёт пишется всегда.

## Вердикты (`Finding`)

| Поле | Значения |
|---|---|
| `verdict` | `attention` (стоит посмотреть), `likely_artifact` (вероятно, артефакт), `not_significant` (незначимо) |
| `confidence` | уверенность модели: `low`, `medium` или `high` |
| `significance` | значимость по мнению модели; значимость детекторов хранится в моменте |
| `summary`, `explanation` | суть и объяснение |
| `evidence[]` | факты (`fact`) и метки результатов, откуда они взяты (`source`) |
| `operator_check` | что посмотреть оператору |

**Порядок моментов.** `RunData.ordered()` сортирует по вердикту («стоит посмотреть», без оценки, артефакт,
незначимо), затем по значимости детекторов. Первые `top_k` моментов без вердикта «незначимо» идут в карточки,
остальные — в таблицу.

## Журнал (`trace.jsonl`)

События по порядку:
- `start` — системный промпт и обзор;
- `moment` — промпт момента;
- `llm` — ответ модели, токены, время;
- `tool` — вызов ручки, аргументы, результат;
- `validation` — проверка;
- `budget` — сработавший бюджет;
- `llm_error` — сбой модели;
- `finish` — итог и сумма токенов.

Это всё, что видела модель, поэтому журнал служит и аудитом профиля `external`.

## Отчёт

Самодостаточный HTML: стили и SVG встроены, внешних скриптов нет. Разделы:

1. **Шапка** — сессия, длительность, сценарий, модель, приватность, id разбора и оговорка о первичном контуре.
2. **Итог** — заголовок и абзац модели или шаблонный текст, счётчики вердиктов, качество данных.
3. **Ход сессии** — вероятности 6 эмоций, пронумерованные полосы моментов (цвет — вердикт), дорожки «лицо» и
   «речь».
4. **Карточки** — интервал, типы, вердикт и уверенность, обе значимости, тексты модели или данные детекторов с
   пометкой «Без объяснения модели», мини-график ±15 с, ссылка на запись.
5. **Остальные кандидаты** — таблица.
6. **Методика** — правила детекторов, параметры профиля, модели распознавания, ссылки на `findings.json` и
   `trace.jsonl`.

Ссылка на момент — `AFFECTRA_PUBLIC_URL/recordings/<id>?t=<секунда>`; страница записи открывает видео на этой
секунде. В профиле `external` имя сессии в отчёт не попадает.

## Тесты

`tests/agent/test_loop.py` — поддельная модель по сценариям, ручки настоящие (MCP-сервер в процессе). Сценарии:
- правильный ход разбора;
- текст вместо вызова и JSON в тексте;
- дважды неверное доказательство;
- повторы и исчерпанный бюджет вызовов;
- недоступная модель;
- исчерпанное время;
- обезличивание в профиле `external`;
- правила проверки;
- клиент LLM: разбор вызовов и повтор после 503;
- запуск `mcp_server.py` дочерним процессом;
- файлы разбора.

`tests/agent/test_report.py` — отчёт без модели и с вердиктами.
